Las tres implementaciones enlazadas: sumar sin perder nada

Tres funciones suman los elementos de un TAD sobre nodos usando solo su contrato, y lo dejan como estaba. Cada TAD tiene n = 12 elementos. Un avance es una ejecución de actual = actual->siguiente en el ciclo de nodoEn, que es lo que usa obtener(p) para llegar a la posición p.

1. La lista, por posición

int sumar(Lista &l) {
  int suma = 0;
  int p = 0;
  while (p < l.tamano()) {
    suma = suma + l.obtener(p);
    p = p + 1;
  }
  return suma;
}

2. La cola, dándole la vuelta

int sumar(Cola &c) {
  int suma = 0;
  int k = 0;
  int n = c.tamano();
  while (k < n) {
    suma = suma + c.frente();
    c.encolar(c.frente());
    c.desencolar();
    k = k + 1;
  }
  return suma;
}

3. La pila, con una auxiliar

int sumar(Pila &p) {
  Pila aux;
  int suma = 0;
  while (!p.vacia()) {
    suma = suma + p.tope();
    aux.apilar(p.tope());
    p.desapilar();
  }
  while (!aux.vacia()) {
    p.apilar(aux.tope());
    aux.desapilar();
  }
  return suma;
}

4. ¿Cuál es Θ(n²) en tiempo?

Lo que quedó

Las tres implementaciones tienen los extremos a mano y el medio lejos. La pila y la cola solo trabajan en los extremos, así que sumar cuesta Θ(n) aunque haya que sacar y volver a meter cada elemento: la cola lo hace en el sitio, reservando y liberando un nodo por vuelta, y la pila pide Θ(n) de espacio en la auxiliar. La lista ofrece el medio, pero llegar a la posición p cuesta Θ(p), y pedir las posiciones una por una desde afuera suma Θ(n²).
