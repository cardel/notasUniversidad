polimorfico: msort para cualquier tipo

La versión de msort que ordena enteros sirve solo para List[Int], porque < está definido para Int y no para un tipo cualquiera. La versión de abajo abre el tipo con [T] y recibe la comparación como un parámetro más. Responda las cuatro preguntas; cada opción errada explica en qué se equivoca.

1. La versión genérica

■ la firma: el tipo T y la comparación que entra por parámetro ■ menorQue reemplaza al operador < dentro de merge ■ cada llamada recursiva vuelve a pasar menorQue

El cuerpo es el mismo de la versión para enteros: las dos líneas de merge que comparaban con < ahora llaman a menorQue, y nada más cambió.

4. Lo que se lleva de aquí

El parámetro de tipo y la función de comparación resuelven dos problemas distintos. [T] abre el tipo de los elementos, y con eso splitAt, :: y el match sobre la tupla siguen funcionando igual: ninguno necesita saber qué guarda la lista. Lo único que sí lo necesitaba era la comparación, y por eso es lo único que entra por parámetro.

La firma tiene dos listas de parámetros, (xs: List[T]) y (menorQue: (T, T) => Boolean), y las dos hay que llenarlas en cada llamada, también en las recursivas. Escribir msort(izq) a secas deja una función a medio aplicar donde merge espera una lista, y el compilador lo detiene ahí.

El nombre menorQue describe cómo se usa el resultado, no obliga a nada: msort solo llama a la función y mira si devolvió true. Pasarle (x, y) => x > y ordena de mayor a menor con el mismo cuerpo, y pasarle una comparación sobre un campo ordena por ese campo. El criterio de orden sale del lugar donde se llama, no de donde está escrito el algoritmo.
