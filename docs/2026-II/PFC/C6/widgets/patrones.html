patrones: qué caso del match corresponde con la lista

Un patrón de lista describe una forma, no un contenido: Nil es la lista sin cabeza y x :: xs es la lista que tiene una. A partir de esos dos se escriben patrones más estrictos, que fijan cuántos elementos vienen antes del Nil final. Abajo hay cinco listas, una por ronda. Para cada una diga cuál de los cuatro casos de describir es el que corre.

1. Los dos patrones básicos

Nil corresponde con la lista vacía y es el caso base; x :: xs corresponde con cualquier lista que tenga cabeza, y liga la cabeza en x y la cola en xs. Con esos dos alcanza para recorrer una lista completa:

def sumar(lst: List[Int]): Int = lst match {
  case Nil     => 0
  case x :: xs => x + sumar(xs)
}

sumar(List(1, 2, 3))  // 6

5. Lo que se lleva de aquí

Los cuatro patrones no son cuatro preguntas que el match evalúe para escoger la mejor. Son una lista ordenada: el valor se compara con el primero, y si corresponde, ahí termina. De las cinco listas de arriba, tres corresponden con dos o más casos a la vez, y en todas el que corrió fue el de más arriba. Por eso los patrones de longitud fija van antes que x :: xs, y por eso Nil suele ir de primero: es el único que no compite con nadie.

Lo que cada patrón liga también viene de su forma. case x :: y :: Nil da nombre a dos elementos y exige que no haya un tercero; case x :: xs da nombre a la cabeza y agrupa todo lo demás en una lista, sin decir cuántos elementos tiene. De ahí que el cuerpo del último caso pueda llamar xs.length mientras los otros tres ya saben la longitud sin consultarla.

El mismo nombre no puede aparecer dos veces en un patrón: case x :: x :: xs no es válido. Comparar los dos primeros elementos se escribe ligando nombres distintos y poniendo la comparación en el cuerpo o en una guarda.
