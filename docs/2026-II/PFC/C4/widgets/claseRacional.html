claseRacional: prediga lo que responde el REPL

Una clase de tres líneas y un objeto creado con new. Abajo hay cuatro expresiones y, para cada una, cinco respuestas posibles: elija la suya antes de ver la del REPL. Dos devuelven un entero, una imprime algo que no se parece a un número y la cuarta no llega a compilar.

1. La clase y el objeto

class Racional(x: Int, y: Int) {
def numer = x
def denom = y
}
scala> val x = new Racional(1, 2)
val x: Racional = Racional@2faf6e4a

La cabecera recibe el 1 y el 2 con los nombres x y y. El cuerpo declara dos def: numer y denom. El val x del REPL es otro nombre, el del objeto, y es el que se usa a la izquierda del punto.

2. Prediga las cuatro respuestas

3. Dentro de la clase x vale 1. ¿Por qué entonces x.x falla y x.numer responde 1?

4. Lo que se lleva de aquí

La definición introduce dos cosas con el mismo nombre: el tipo Racional y el constructor Racional. Los nombres de la cabecera, x y y, no entran en ese trato: sirven dentro del cuerpo y nadie los alcanza desde afuera. Lo que el cliente selecciona con el punto es la lista de def del cuerpo, y por eso el numerador se pide como x.numer aunque adentro se llame x.

La respuesta Racional@2faf6e4a es la del toString heredado, que imprime el nombre de la clase y una dirección. Para que el REPL escriba 1/2 hay que escribirle a Racional su propio toString.
