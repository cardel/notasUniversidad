punto2d: la tabla de Punto antes de correrla

Puntos en el plano con lo mismo que se usó en Racional: métodos, un operador simbólico y toString. Antes de ejecutar nada, escriba el tipo y el valor que devuelve cada expresión; después siga la corrida paso a paso y compare. Los decimales cuentan.

1. La clase

class Punto(val x: Double, val y: Double) {
def +(p: Punto): Punto = new Punto(x + p.x, y + p.y)
def distancia(p: Punto): Double = {
val dx = x - p.x
val dy = y - p.y
math.sqrt(dx * dx + dy * dy)
}
override def toString: String = "(" + x + ", " + y + ")"
}

La cabecera declara los dos parámetros con val. En Racional la cabecera es class Racional(x: Int, y: Int), sin val, y lo que el cliente ve son los métodos numer y denom.

Las dos expresiones del REPL que crean los puntos: val p1 = new Punto(1, 2) y val p2 = new Punto(4, 6).

4. El mismo acceso en Racional

Con val r = new Racional(1, 2), r.numer responde 1 y r.x no compila: value x is not a member of Racional. ¿Qué lo explica?

5. Lo que se lleva de aquí

El .0 no es adorno. La cabecera pide Double, así que el literal 1 se convierte al entrar: p1.x responde 1.0, y toString escribe (1.0, 2.0) aunque el objeto se haya creado con new Punto(1, 2).

distancia da lo mismo en los dos sentidos porque dx y dy cambian de signo y el cuadrado lo borra: −3.0 y −4.0 en un sentido, 3.0 y 4.0 en el otro, y math.sqrt(9.0 + 16.0) es 5.0 en ambos.

(p1 + p2).x corre el + por segunda vez y lee el campo del punto que acaba de construirse; p1 sigue en (1.0, 2.0) al final de la corrida. El + construye, no modifica.

Y el acceso que no existe: r.x. Que un nombre responda desde afuera no depende del valor que guarda, sino de que esté declarado como miembro — con val en la cabecera, como en Punto, o con def en el cuerpo, como numer.
