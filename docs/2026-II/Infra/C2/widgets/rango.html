El rango se parte en dos mientras supere el grano

Con TBB no se calculan cortes: se describe el rango y el grano, y el planificador lo parte. Prediga en cuántos subrangos queda antes de ver el árbol; después baje el grano a 1 y mire lo que sale.

1. El rango y el grano

n = 1.000
grano = 100
tbb::blocked_range<int>(0, 1000, 100)
Un subrango se parte por la mitad mientras su tamaño supere el grano. Sin tercer argumento el grano vale 1 y decide el particionador automático.

2. Antes de ver el árbol

Con n = 1.000 y grano 100, ¿en cuántos subrangos queda el rango?

3. El árbol

Verde: las hojas, que son las tareas que se reparten entre los hilos. Con grano 1 y n = 1.000 salen mil hojas de un elemento: por eso el particionador automático deja de partir cuando ya hay tareas suficientes para los hilos que hay, y por eso con tareas baratas se sube el grano.

4. Antes de mirar los tiempos, mire el resultado

1long sumVectorSeq() {
2 long result = 0;
3 for (int i = 0; i < VECTOR_SIZE; i++) result += v[i];
4 return result;
5}

Con u[i] = 20, v[i] = 10 y un millón de elementos, la versión paralela imprime 2×10⁸ y la secuencial 10⁷. Compila, corre y no falla. ¿Qué está pasando?
