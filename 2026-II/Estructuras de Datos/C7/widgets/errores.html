Compila sin avisos y aun así está mal

Este fragmento pasa gcc -Wall -Wextra sin una sola queja, y tiene dos errores de memoria: uno rompe la regla de verificar y otro pierde un bloque para siempre. Haga clic en la línea donde nace cada uno.

1. Señale las líneas culpables

Cada clic responde: las líneas inocentes explican por qué lo son. Los dos errores rompen dos de las tres reglas del contrato con el montículo.

2. El arreglo

Con los dos errores a la vista, la versión sana: verificar cada reserva antes de usarla, y liberar (o no perder) el bloque viejo de b antes de reasignar el puntero.

int *a = malloc(n * sizeof(int));
int *b = malloc(n * sizeof(int));
if (a == NULL || b == NULL) {
/* reportar y salir sin tocar los bloques */
} else {
a[0] = 1;
b[0] = 2;
free(b); /* devolver antes de reasignar */
b = malloc(2 * n * sizeof(int));
/* ... verificar b de nuevo, usar, y al final ... */
free(a);
free(b);
}
Cada malloc con su NULL, cada malloc con su free, y ningún puntero pierde su bloque: las tres reglas de la clase, completas.
